Chuỗi bằng chứng — chống ảo giác bằng máy

Đây là phần đáng mang đi nhất của DAI Nexus. Không phải lời nhắc "hãy trung thực", mà là bốn cổng cơ học mà agent không thể nói vòng qua.

01 Lớp 1 — Evidence do máy ghi

Agent không tự viết bằng chứng. Nó chạy lệnh kiểm chứng qua run_check.py, script này thực thi, thu output, redact secret trong bộ nhớ, rồi ghi JSON nguyên tử:

Ba trường quyết định tính không-thể-giả: tree_sha (trạng thái cây làm việc lúc chạy), timestamp_utc, và exit_code thật của tiến trình con.

02 Lớp 2 — Stop-hook gate

Cuối mỗi lượt, hook gọi verify_gate.py. Nếu có file code thay đổi, gate đòi một evidence hợp lệ. Sáu phép kiểm tra độc lập:

scripts/lite/verify_gate.py:224so khớp tree-sha
def _validate_tree(ev: dict, current_tree: str) -> list[str]:
    ev_tree = ev.get("tree_sha", "")
    if not ev_tree:
        return ["MISMATCH: tree_sha missing in evidence"]
    if ev_tree == current_tree:
        return []
    # Both DIRTY: compare HEAD part only (index may have evolved)
    if ev_tree.startswith("DIRTY:") and current_tree.startswith("DIRTY:"):
        if ev_tree.split(":")[1] == current_tree.split(":")[1]:
            return []
    if ev_tree.startswith("NONGIT") or current_tree.startswith("NONGIT"):
        return []
    return [
        f"MISMATCH: tree_sha changed since evidence was written. "
        f"Evidence: {ev_tree!r}, Current: {current_tree!r}"
    ]
Cổng này từng chặn chính tác giả
Trong lúc dựng v0.6.0, gate trả về BLOCKED vì README và VERSION được sửa sau khi test chạy — tree-sha lệch. Phải chạy lại test rồi mới commit được. Đó là dấu hiệu cổng hoạt động, không phải phiền toái.

03 Lớp 3 — Execution policy fail-closed

Guardrail dạng văn bản là phán đoán; policy_check.py là thực thi. Deny-pattern hiện hành đọc từ .dainexus/execution-policy.yaml:

  • rm\s+(-[a-zA-Z]*r[a-zA-Z]*f|-[a-zA-Z]*f[a-zA-Z]*r)
  • git\s+push\s+.*(--force|\s-f(\s|$))
  • git\s+reset\s+--hard
  • git\s+clean\s+-[a-zA-Z]*f
  • DROP\s+(TABLE|DATABASE)
  • curl\s+[^|]*\|\s*(ba|z)?sh
  • wget\s+[^|]*\|\s*(ba|z)?sh
  • chmod\s+777
  • Remove-Item\s+.*-Recurse\s+.*-Force

Điểm quan trọng là hướng fail: file policy thiếu, rỗng, hỏng, hay mode lạ đều chặn chứ không cho qua:

scripts/lite/policy_check.py:85
def cmd_check(tool: str, args: list[str]) -> int:

    mode = policy.get("mode", "strict")

04 Lớp 4 — Runtime ledger

Một dev server bị bỏ quên vô hình với mọi loại test: build xanh, test pass, RAM cứ leo. Mọi process dài hạn phải khởi động qua lease:

VERIFY Template 4
RUNTIME LEDGER
OPENED:  <lease_id> role=<..> pid=<..>
CLOSED:  <lease_id>
LEAKED:  none | <lease_id list>
COMMAND: python scripts/lite/runtime_lease.py status
VERDICT: CLEAN | LEAKED

Lệnh run tái dùng instance đang sống thay vì mở cái thứ hai; reap dọn mọi lease không phải policy=keep. Trên Windows, kiểm tra process sống không được dùng os.kill(pid, 0) — nó gọi TerminateProcess và giết thật:

scripts/lite/runtime_lease.py:39
def pid_alive(pid: int) -> bool:
    if pid <= 0:
        return False
    if os.name == "nt":
        r = subprocess.run(
            ["tasklist", "/FI", f"PID eq {pid}", "/NH", "/FO", "CSV"],
            capture_output=True, text=True, timeout=10,
        )
        return f'"{pid}"' in r.stdout
    try:
        os.kill(pid, 0)
        return True
    except ProcessLookupError:
        return False
